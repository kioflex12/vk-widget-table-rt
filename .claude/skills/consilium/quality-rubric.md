# Quality-рубрика consilium (quality-gate)

Оценка качества предлагаемого решения/изменения для VK-виджета таблицы RT.
Прогоняется КАЖДЫЙ раз, когда работает consilium — обязательный компонент verdict'а.

Для каждого пункта вынеси: `block` (нарушение) / `worry` (caveat) / `ok`.
Суди по логике изменения, НЕ по комментариям в коде на слово.

## Уровень 0 — дешёвые детерминированные проверки (сделай их ПЕРВЫМИ)
Если хоть одна даёт `block` — LLM-разбор дальше не нужен, итог сразу `block`:
- **DOM-контракт.** Каждый `document.getElementById('X')` в [app.js](../../../app.js) имеет соответствующий `id="X"` в [index.html](../../../index.html), и наоборот для новых. Проверь grep'ом.
- **Синтаксис.** JS не падает при загрузке (нет очевидных синтаксических ошибок, незакрытых скобок, обращений к `null`-элементам без гварда).
- **Символы.** Все вызываемые функции/поля реально существуют в проекте (grep по реальному коду, не по памяти).

## Уровень 1 — логика и качество

1. **Фикс первопричины.** Решение чинит источник, а не симптом. ЗАПРЕЩЕНО как основной фикс: глушение ошибки (пустой `catch`, проглатывание исключения без сообщения пользователю), обход валидации, «показать пустую таблицу вместо ошибки, чтобы не падало». Пустой экран/тихий провал — это баг, а не фикс. (Ср. историю коммитов: «white screen», «guard against undefined vkBridge».)

2. **Безопасность вывода (XSS).** Любые данные из Google Sheets (`nick`, `vk`, `rt`) при вставке в DOM экранируются (`escapeHtml`) или вставляются через `textContent`/`createElement`, НЕ через `innerHTML` со склейкой. Ссылки игрока проходят через allowlist VK-доменов (`buildProfileUrl` / `VK_DOMAINS`) — нельзя пропускать произвольный `href` (javascript:, чужой домен).

3. **Секреты не в репозитории.** Токены VK, `access_token`, service-account JSON, OAuth client secret, refresh-token — НЕ коммитятся. Community-токен добывается в рантайме через VK Bridge, не хардкодится. Любой новый секрет → в `.gitignore`, не в код. Публичные значения (`PUB_ID` опубликованной таблицы, `app_id`) — не секрет, это ок.

4. **Robustness данных.** Парсинг CSV/ответа устойчив к: пустой таблице, строкам без части колонок, кавычкам/запятым/переносам внутри ячеек, лишней пустой последней строке, заголовку. Отсутствие данных показывается как понятная ошибка, а не как молчаливо пустой список.

5. **VK-виджет контракт.** Объект виджета (`buildWidgetObject`) валиден для `appWidgets.update` type=`table`: есть `title`/`head`/`body`, `body` — массив массивов ячеек, `code` имеет форму `return {...};`. Токен запрашивается с нужным scope (`app_widget`). Прямой `fetch` к VK API НЕ используется (CORS) — только через `VKWebAppCallAPIMethod`.

6. **Совместимость режимов.** Изменение не ломает разделение public/admin view по `vk_group_id` и не возвращает «белый экран» на мобилке (public-таблица должна грузиться без обязательного ожидания VK Bridge init).

7. **Release-инвариант.** Если меняется `app.js`/`styles.css`/`index.html` — предусмотрен bump `VERSION` (patch) в `app.js` и обновление cache-busting `?v=...` в `index.html`. Без этого пользователи GitHub Pages не получат новый код. (Отсутствие bump'а — как минимум `worry`.)

**Итоговый verdict gate'а:**
- `block` — нарушение Уровня-0, либо пунктов 1-3, либо критичное 4-6 → решение НЕ выдавать.
- `worry` — есть caveat (например забыт bump версии, слабая обработка edge-case) → выдать с явным предупреждением.
- `ok` — нарушений нет.
